# Wanna Run? 🏃‍♀️💨

เว็บแอปบนมือถือสำหรับ **ชวนเพื่อนไปวิ่งด้วยกัน** — สร้างก๊วน นัดสถานที่ แชร์ตำแหน่ง
จับระยะทางด้วย GPS พร้อมภารกิจและมินิเกมให้สนุกไปกับการซ้อม

ออกแบบเป็น mobile-first PWA (ติดตั้งลงหน้าจอโฮมได้ ใช้งานออฟไลน์ได้) ภาษาไทยทั้งแอป

## ฟีเจอร์

| ฟีเจอร์ | รายละเอียด |
|---|---|
| 🙂 **รูปโปรไฟล์** | อัปรูปจากกล้องหรือคลังภาพ ย่อเป็น 256px ก่อนอัปขึ้น Storage เพื่อนเห็นรูปทุกที่ในแอป |
| 👟 **เพิ่มเพื่อน** | สแกน QR ด้วยกล้อง หรือกรอกรหัสเพื่อนประจำตัว (เช่น `RUN-7KQ2`) ส่งคำขอ / ตอบรับ |
| 📷 **QR เพิ่มเพื่อน** | โชว์ QR ของตัวเองให้เพื่อนสแกน และเปิดกล้องสแกนของเพื่อนได้ในแอป โค้ดเป็นลิงก์จึงสแกนด้วยกล้องของเครื่องก็เปิดแอปมาหน้าเพิ่มเพื่อนให้เลย |
| 👥 **สร้างกลุ่ม** | ตั้งก๊วนวิ่ง เพิ่ม–นำสมาชิกออก และชวนทั้งกลุ่มได้ในคลิกเดียว |
| 📣 **ชวนกันวิ่ง** | สร้างคำชวน: หัวข้อ สถานที่ วันเวลา ระยะเป้าหมาย ข้อความ พร้อมดูว่าใครตอบรับบ้าง |
| 🌳 **เลือกสถานที่** | สวน/ลู่วิ่งยอดนิยมพร้อมระยะรอบ, เรียงตามระยะห่างจากคุณ, ใช้ตำแหน่งปัจจุบัน หรือปักหมุดเองบนแผนที่ |
| 🔔 **แจ้งเตือน** | แจ้งเตือนระบบ (Web Notification) + ศูนย์การแจ้งเตือนในแอป + สั่นเมื่อครบทุก 1 กม. |
| 📍 **แสดง & แชร์ตำแหน่ง** | แผนที่สดแสดงตำแหน่งคุณและเพื่อนที่แชร์อยู่ เปิด/ปิดการแชร์ และส่งลิงก์ตำแหน่งผ่าน Web Share |
| ⏱️ **จับระยะทาง** | ติดตามด้วย GPS (`watchPosition`) คำนวณระยะแบบ Haversine พร้อมเวลา เพซ แคลอรี่ และเส้นทางบนแผนที่ |
| 🎮 **มินิเกม** | *แตะให้ทันจังหวะ*, *วงล้อภารกิจ* (วันละครั้ง), *ควิซคนรักวิ่ง* |
| 🎯 **ภารกิจ** | ภารกิจรายวัน/รายสัปดาห์/สะสม เก็บ XP เหรียญ เลเวล และเหรียญตรา |

## เริ่มใช้งาน

```bash
npm install
npm run dev      # เปิด http://localhost:5173
npm run build    # สร้างไฟล์ production ที่ dist/
npm run preview  # ลองรันไฟล์ production
```

เปิดจากมือถือให้ใช้ `npm run dev -- --host` แล้วเข้าจาก IP ของเครื่อง
(เบราว์เซอร์จะให้สิทธิ์ GPS เฉพาะบน `https://` หรือ `localhost` เท่านั้น)

## ข้อกำหนดของเบราว์เซอร์

ฟีเจอร์ที่ต้องขอสิทธิ์จากผู้ใช้และ **ทำงานเฉพาะบน `https://` หรือ `localhost`**:

| ฟีเจอร์ | API ที่ใช้ | ถ้าใช้ไม่ได้ |
|---|---|---|
| จับระยะทาง / แผนที่ | Geolocation | มีโหมดจำลองให้ทดลอง |
| สแกน QR | getUserMedia (กล้องหลัง) | สลับไปกรอกรหัสเองได้ |
| แจ้งเตือน | Notification | ยังเห็นแจ้งเตือนในแอปตามปกติ |

การถอดรหัส QR ใช้ `BarcodeDetector` ของเบราว์เซอร์ถ้ามี (Chrome/Android เร็วกว่า)
ถ้าไม่มี เช่นบน Safari จะโหลด `jsQR` มาถอดเองแบบอัตโนมัติ

## เชื่อมต่อ Supabase (ใช้กับเพื่อนจริงข้ามเครื่อง)

แอปทำงานได้ทั้งแบบมีและไม่มีเซิร์ฟเวอร์ ถ้าไม่ตั้งค่าสองตัวแปรด้านล่างจะถอยไปเก็บข้อมูลในเครื่องอย่างเดียว

### 1. สร้างตารางและสิทธิ์

เปิด Supabase Dashboard → **SQL Editor** → **New query** วางเนื้อหาทั้งไฟล์
[`supabase/schema.sql`](supabase/schema.sql) แล้วกด Run (รันซ้ำได้ ไม่พัง)

จากนั้นรัน [`supabase/avatars.sql`](supabase/avatars.sql) เพิ่มอีกไฟล์ สำหรับรูปโปรไฟล์
(สร้างคอลัมน์ `avatar_url` และถังเก็บไฟล์ `avatars` พร้อมสิทธิ์ให้แต่ละคนเขียนได้เฉพาะโฟลเดอร์ตัวเอง)

> ถ้าเคยรัน `schema.sql` เวอร์ชันแรกไปแล้ว ให้รัน `supabase/fix-invite-recursion.sql`
> และ `supabase/fix-2-invite-policies.sql` ตามลำดับ เพื่ออัปเดต policy ให้ตรงกับเวอร์ชันล่าสุด

ไฟล์นี้สร้าง `profiles`, `friendships`, `groups`, `group_members`, `invites`,
`invite_replies`, `locations` พร้อม **Row Level Security** ครบทุกตาราง และเปิด Realtime
ให้ตำแหน่งกับคำชวนวิ่งอัปเดตสด ๆ

หลักการของสิทธิ์:

- โปรไฟล์คนอื่นเห็นได้เฉพาะคนที่เป็นเพื่อนหรือมีคำขอค้างกันอยู่
- ค้นหาด้วยรหัสเพื่อนต้องผ่านฟังก์ชัน `send_friend_request()` เท่านั้น
  จึงไล่สุ่มรหัสเพื่อดูดข้อมูลคนอื่นไม่ได้
- ตำแหน่งของเพื่อนอ่านได้ต่อเมื่อ **เป็นเพื่อนกัน และเจ้าตัวเปิดแชร์อยู่**
- คำตอบรับคำชวนแก้ได้เฉพาะของตัวเอง เจ้าภาพเท่านั้นที่แก้ตัวคำชวนได้

### 2. ตั้งค่าการเข้าสู่ระบบ

Dashboard → **Authentication → Providers → Email** เปิดใช้งานไว้
ถ้ายังไม่ได้ตั้ง SMTP ให้ปิด **Confirm email** ไปก่อน ผู้ใช้จะเข้าใช้ได้ทันทีหลังสมัคร

### 3. ใส่คีย์

```bash
cp .env.example .env
```

แล้วเติม `VITE_SUPABASE_ANON_KEY` จาก Dashboard → **Project Settings → API → anon public**

คีย์ `anon` เปิดเผยได้ตามการออกแบบของ Supabase (ความปลอดภัยอยู่ที่ RLS ไม่ใช่ตัวคีย์)
แต่อย่าใส่ `service_role` ลงในโค้ดฝั่งหน้าเว็บเด็ดขาด — คีย์นั้นข้าม RLS ได้ทั้งหมด

ตอน deploy บน Render ให้ใส่ตัวแปรทั้งสองที่ **Environment** ของ service
เพราะ Vite ฝังค่าลงไปตอน build

## Deploy ขึ้นเว็บ

แอปเป็น static site ล้วน (ไม่มีเซิร์ฟเวอร์/ฐานข้อมูล) จึงขึ้นโฮสต์ไหนก็ได้ที่เสิร์ฟไฟล์ static

### Render

ใน repo มี `render.yaml` เตรียมไว้แล้ว — เข้า [Render Dashboard](https://dashboard.render.com/select-repo?type=blueprint)
เลือก **New → Blueprint** แล้วชี้มาที่ repo นี้ Render จะอ่านค่าจากไฟล์เองทั้งหมด
(build ด้วย `npm ci && npm run build`, เสิร์ฟจาก `dist/`, rewrite ทุกเส้นทางไปที่ `index.html`)

ใช้แผน Free ได้ และจะได้ URL แบบ `https://wanna-run.onrender.com`

> ต้อง deploy ผ่าน **https** เท่านั้น เพราะเบราว์เซอร์ให้สิทธิ์ GPS และการแจ้งเตือน
> เฉพาะบน https หรือ localhost — Render ให้ HTTPS มาอยู่แล้ว

### โฮสต์อื่น

`npm run build` แล้วอัปโหลดโฟลเดอร์ `dist/` ขึ้น Netlify / Vercel / Cloudflare Pages / GitHub Pages
อย่าลืมตั้ง SPA fallback ให้ทุกเส้นทางตกมาที่ `index.html`

## หมายเหตุเรื่องข้อมูล

เวอร์ชันนี้ทำงานแบบ **local-first ไม่มีเซิร์ฟเวอร์กลาง** — ข้อมูลทั้งหมด
(โปรไฟล์ เพื่อน กลุ่ม นัดวิ่ง ประวัติการวิ่ง) เก็บใน `localStorage` ของเครื่องคุณเท่านั้น
ไม่มีการส่งออกไปที่ไหน

ผู้ใช้ใหม่จะเริ่มจากก๊วนว่างเปล่า ไม่มีเพื่อน กลุ่ม หรือนัดวิ่งตัวอย่างติดมาให้

เมื่อเพิ่มเพื่อนแล้ว สิ่งเหล่านี้ยังเป็น **ข้อมูลจำลอง** เพราะยังไม่มีเซิร์ฟเวอร์กลาง:

- เพื่อนที่เพิ่มด้วยรหัสจะถูกสร้างโปรไฟล์ขึ้นจากตัวรหัส ไม่ได้เชื่อมกับคนจริงที่ถือรหัสนั้น
- ตำแหน่งของเพื่อนบนแผนที่ (เดินสุ่มรอบจุดประจำของแต่ละคน)
- การตอบรับคำขอเป็นเพื่อนและการตอบรับคำชวนวิ่ง (ตอบกลับอัตโนมัติหลังไม่กี่วินาที)
- อันดับคะแนนมินิเกมของเพื่อน

ส่วนที่เป็น **ของจริง**: ตำแหน่งของคุณเอง การจับระยะทาง/เพซ/เส้นทางจาก GPS
การแจ้งเตือนของเบราว์เซอร์ การสั่น และการแชร์ลิงก์ตำแหน่ง

การต่อยอดให้ใช้กับเพื่อนจริงข้ามเครื่องต้องเพิ่มแบ็กเอนด์ (บัญชีผู้ใช้ + realtime)
โดย `src/state/store.tsx` ถูกแยกไว้เป็นชั้นเดียวที่แตะข้อมูล จึงเปลี่ยนไปเรียก API ได้โดยไม่กระทบหน้าจอ
